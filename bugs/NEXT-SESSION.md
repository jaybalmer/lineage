> **BUILT AND SHIPPED via #243, superseded. Was: `bugs/2026-09-08-localstorage-quota-userentities.md` (BUG-188, P0). PIPELINE-SAFE on the code, but read the trap below before running it unattended. Four decisions, all with recommended defaults, build-ready on those defaults.**
> Sentry caught `QuotaExceededError` out of `addClaim` on a signed-in iPhone at `/snowboarding/boards`, release `cdb0224`, September 8 13:24 UTC. The boards page is where it fired, not where it lives. `userEntities` is persisted to localStorage, and `loadDbEntities` (`lineage-store.ts:881-907`) fills it with a full mirror of `places` + `boards` + `orgs` + `events` for every signed-in member, refetched by `Nav` on every mount. Measured live today: 2,599,065 serialized characters, 4.96 MB in UTF-16, against WebKit's hard 5 MB per-origin quota. The events import across #240 to #242 added the last 1.22 MB the day before the error fired.
>
> **This is P0 because zustand v5 runs `localStorage.setItem` synchronously inside `set()` with no `try`/`catch`** (`node_modules/zustand/middleware.js:300`, `:358-373`), so once a member is over quota EVERY store action throws, not just this one. In `addClaim` the throw lands on the first line (`:417`), so the `getSession()` block below it never runs and the claim is never written to the database. The member taps add and nothing happens. There is no workaround.
>
> **The fix is small and the trap is not in the fix, it is in what is already on disk.** `partialize` governs what is WRITTEN; zustand shallow-merges the stored blob back over the initial state on READ, so a browser that already persisted the mirror keeps hydrating it after the fix unless the persist `version` is bumped with a `migrate` supplied alongside. A version bump with NO `migrate` discards the entire persisted state and would drop `onboardingComplete`, `membership` and `activeCommunitySlug` for every existing member. Both halves are D3 in the brief. Smoke on a real iPhone: the quota is a WebKit limit, not a screen width, so device mode in Chrome DevTools will not reproduce it.
