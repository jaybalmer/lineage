## How the loop works

This mirrors the bug loop, with one difference: features have no `BUG-NNN` id, so they
reconcile off `bugs/SHIP-LOG.md` (the `type: feature` entries) and the git log, not off a
queue-to-shipped id match.

0. **Reconcile (first thing each digest/triage run).** Read the merged-PR list on `main`
   since the last run. For each merged FEATURE PR (a `feat`/`chore` subject with a `(#NN)`,
   or a `bugs/SHIP-LOG.md` `type: feature` entry flipping to merged): if it matches a brief
   staged in `features/`, (a) move that brief from the Queue below to **Shipped** with the
   PR number, (b) archive the brief to `features/archive/<date>-<slug>.md`, (c) mirror on the
   Drive side per the brief-filing convention: move the authoring copy from Drive
   `Operations/` to `Operations/Archive/`, add its line to `Operations/Archive/_INDEX.md`, and
   repoint the file's row in Drive `CLAUDE.md`'s Documents table (skip if Drive is unreachable
   or the match is uncertain, and note it), and (d) repoint `features/NEXT-FEATURE.md`
   "Build this" to the next ready brief. Keep edits idempotent.
1. **Draft.** A new product capability gets a build-ready brief (authored in Drive
   `Operations/`, then staged as the build-ready copy in `features/`). Any product/design
   choice gets a recommended default in a "DECISIONS (review before building)" block so the
   brief never blocks on Jay.
2. **Queue.** The ready briefs are listed below, ordered by readiness + launch value.
3. **Build.** Jay says "start a feature session" in Claude Code. The repo `CLAUDE.md`
   auto-loads and points at `features/NEXT-FEATURE.md`. Claude Code builds the lead (or a
   named brief), ships a PR, and logs to `bugs/SHIP-LOG.md` (`type: feature`, `ids: none`,
   a `scope:` slug). The next reconcile marks it shipped here.

Manual run any time: just say "run bug triage" (the same run reconciles features too) or
update this file by hand.

**Where things live (Drive, as of June 29, 2026):**
- Product spec (`PB-0XX.docx`, the what/why) → `Product/`
- Active build brief (the how, by phase) → `Operations/`
- Shipped build briefs → `Operations/Archive/` (see its `_INDEX.md` for the PB → brief → PR map)
- Superseded specs / completed artifacts → `Product/Archive/`

To trace a PB end to end: spec in `Product/` → phase briefs in `Operations/` (active) or `Operations/Archive/` (shipped) → PR in the Shipped section below.
